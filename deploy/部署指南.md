# 开发组管理系统 —— 零成本上线指南

> 目标：**不买域名、不买服务器**，让系统有一个公网链接，团队随时打开。
> 方案：应用跑在 **Render 免费实例**，数据库用 **TiDB Cloud Serverless 免费实例**。

---

## 一、先看清代价（很重要）

这套方案是**真正免费、无需信用卡**的，但免费有免费的限制，你要接受这三条：

| 限制 | 具体表现 | 影响 |
|---|---|---|
| 应用会休眠 | 15 分钟没人访问，实例会自动休眠；下次访问要**等约 1 分钟**唤醒 | 上班第一次打开会卡一会儿，之后就快 |
| 免费实例较小 | 512MB 内存 / 0.1 CPU | 够 10~20 人同时用；大批量导出 Excel 会稍慢 |
| 数据库有额度 | TiDB 免费：5GiB 存储 + 每月 5000 万请求单元 | 你这个系统数据量约 2MB，正常用一年也用不完 |
| 国内访问一般 | Render 节点在新加坡，比国内服务器慢 | 页面打开约 1~3 秒 |

如果以后要"打开就秒开、不睡觉"，Render 的 Starter 套餐约 7 美元/月即可解决，代码一行都不用改。

## 二、架构长这样

```
用户浏览器
    │  https://xxx.onrender.com
    ▼
```

## 三、第一步：建云数据库（约 10 分钟）

### 3.1 注册并创建实例

1. 打开 <https://tidbcloud.com> ，用 GitHub 或邮箱注册（**不需要信用卡**）。
2. 控制台 → **Create Cluster** → 选择 **Serverless**（这是永久免费档）。
3. 区域（Region）建议选 **Singapore**（和后面 Render 节点同区域，延迟最低）。
4. 设置 root 密码，**记下来**，后面填环境变量要用。
5. 创建完成后，点 **Connect** 拿到连接信息，形如：

```
Host:     gateway01.ap-southeast-1.prod.aws.tidbcloud.com
Port:     4000
User:     3xxxxxxx.root
Password: 你刚设的密码
```

> TiDB 免费实例**强制 TLS**，连接时必须带 `--ssl-mode=REQUIRED`（JDBC 用 `sslMode=REQUIRED`）。

### 3.2 导入数据（带结构 + 全部业务数据）

导出文件已经生成好了：`deploy/team_management_db.sql`（约 190KB，含 42 人 / 48 项目 / 227 版本 / 939 条分配）。

在你的电脑上执行（把尖括号内容替换成 3.1 拿到的信息）：

```bash
mysql -h <Host> -P 4000 -u <User> -p --ssl-mode=REQUIRED < deploy/team_management_db.sql
```

> 如果提示 `mysql: unknown option '--ssl-mode'`，说明客户端版本太老，改用 `--ssl`。

### 3.3 验证导入结果

```bash
mysql -h <Host> -P 4000 -u <User> -p --ssl-mode=REQUIRED -e "
select (select count(*) from team_management_db.users) as users,
       (select count(*) from team_management_db.projects) as projects,
       (select count(*) from team_management_db.project_assignments) as assignments,
       (select count(*) from team_management_db.project_versions) as versions;"
```

必须看到 `42 / 48 / 939 / 227` 四个数字，和本地一致才算迁移成功。

## 五、第三步：部署到 Render（约 10 分钟）

### 5.1 注册

打开 <https://render.com> ，用 GitHub 账号登录（**不需要信用卡**）。

### 5.2 创建服务（两种方式，任选）

**方式 A：蓝图方式（推荐，`render.yaml` 已写好）**

1. 控制台 → **New** → **Blueprint**
2. 选择刚导入的 `team-management` 仓库 → **Connect**
3. Render 会自动读出 `render.yaml`，点 **Apply**

**方式 B：手动方式**

1. **New** → **Web Service** → 选仓库
2. Language 选 **Docker**，Region 选 **Singapore**，Instance Type 选 **Free**
3. Health Check Path 填 `/`

### 5.3 填环境变量（关键，别填错）

在服务的 **Environment** 页面添加 4 个变量：

| Key | Value |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `cloud` |
| `DB_URL` | `jdbc:mysql://<Host>:4000/team_management_db?useUnicode=true&characterEncoding=utf8&useSSL=true&sslMode=REQUIRED&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai` |
| `DB_USERNAME` | TiDB 的 User（如 `3xxxxxxx.root`） |
| `DB_PASSWORD` | TiDB 的密码 |

> 注意 `DB_URL` 里写的是 **`/team_management_db`**（库名），不是 `test`。

### 5.4 等构建完成

首次构建要下载 Maven 依赖，**约 5~8 分钟**，日志里看到这两行就成了：

```
Started TeamManagementSystemApplication in x.xxx seconds
Your service is live 🎉
```

访问地址形如：`https://team-management-xxxx.onrender.com`
这个地址就是你的**分享链接**，发给同事即可，不需要域名。

## 七、常见问题

**1. 页面显示 502 / Application failed to start**
看 Render 的 Logs。最常见是数据库连不上：检查 `DB_URL` 里的 Host、端口 4000、库名，以及是否带了 `sslMode=REQUIRED`。

**2. 登录报 500**
多半是数据没导入成功。回到 3.3 校验 4 个数字。

**3. 中文变问号**
`DB_URL` 必须带 `characterEncoding=utf8`，库和表导入时也必须用 utf8mb4（导出的 SQL 已经是 utf8mb4）。

**4. 启动报 OutOfMemoryError**
免费实例只有 512MB。把环境变量 `JAVA_OPTS` 改成 `-XX:MaxRAMPercentage=65 -XX:+UseSerialGC -Xss512k`。

**5. 国内访问太慢，想换国内云**
代码不用改，换平台只改 4 个环境变量。可选：
- **Zeabur**：可选香港节点，$5 额度试用
- **腾讯云 CloudBase 云托管**：需实名，支持 Gitee 拉代码
- **阿里云函数计算 FC**：需实名，有免费额度

### 改代码后更新线上

```bash
git add -A && git commit -m "改动说明" && git push
```

GitHub 收到推送 → Render 自动重新构建部署（约 5 分钟）。

### 数据备份（重要）

TiDB 免费档**不提供自动备份**。建议每周导一次：

```bash
mysqldump -h <Host> -P 4000 -u <User> -p --ssl-mode=REQUIRED --no-tablespaces \
  --single-transaction --default-character-set=utf8mb4 --set-gtid-purged=OFF \
  --databases team_management_db > backup_$(date +%Y%m%d).sql
```

Windows 上直接双击 `deploy/导出数据库.bat` 也行（改成本地导出）。

## 九、必须知道的安全问题 ⚠️

这套系统是按"公司内网自用"设计的，直接放到公网后有三个真实风险：

1. **密码是明文存的**（数据库里就是 `123456789` 这串字符）。数据库一旦泄露，所有人的密码直接暴露。
2. **登录令牌永不过期**：`token` 格式是 `手机号|时间戳`，后端只校验手机号是否存在，不校验有效期。任何人拿到这个字符串就能一直冒用身份，甚至可以手动伪造。
3. **没有登录失败次数限制**：可以被暴力猜密码。

Render 默认提供 HTTPS，传输层是安全的；但上面三条是应用层的问题。

**建议**：先按本指南跑起来验证可用性，然后告诉我，我可以帮你做三件事（改动不大，不影响现有账号）：
- 密码改成 BCrypt 哈希存储，登录时自动迁移
- token 加签名 + 有效期（比如 7 天）
- 登录失败 5 次锁定 10 分钟

## 十、本次改造清单

为了能在云端跑，代码做了这些改动（本地开发方式完全不受影响）：

| 文件 | 改动 | 原因 |
|---|---|---|
| `src/main/resources/application.yml` | `server.port` 改为 `${PORT:8080}` | 云平台通过 `PORT` 环境变量指定端口 |
| 同上 | 数据源改为 `${DB_URL/DB_USERNAME/DB_PASSWORD:本地默认值}` | 云端用环境变量注入，本地仍连 `localhost` |
| 同上 | 增加 HikariCP 连接池上限（默认 8） | 免费数据库连接数有限 |
| `src/main/resources/application-cloud.yml` | 新增 | 云端专用：不打印 SQL、静态资源不缓存（否则重新部署后浏览器拿旧 index.html 会白屏）、关闭 H2 控制台 |
| `Dockerfile` | 新增 | 多阶段构建：Maven 编译 → JRE 8 运行，限制内存占用 |
| `.dockerignore` | 新增 | 排除 node_modules / target / .git，加快构建 |
| `render.yaml` | 新增 | Render 蓝图，一键带出环境变量配置 |
| `deploy/team_management_db.sql` | 新增 | 完整数据导出（已把 `utf8mb4_0900_ai_ci` 统一成 `utf8mb4_unicode_ci`，保证 TiDB 兼容） |
